# Development

Use pnpm 12.16.1. pnpm manages the project's Node.js runtime, pinned to 26.13.0
in `package.json` and verified by checksums in `pnpm-lock.yaml`.

```sh
pnpm install
pnpm node --version
pnpm dev
```

Run project commands through pnpm so they use the managed Node.js version.
To upgrade to the newest Node.js 26 release, run `pnpm runtime set node 26`
and update `.node-version` to the resolved version. Commit the updated manifest,
lockfile, and `.node-version` together.

Cloudflare Workers runs the deployed app; this Node.js version is for local
development and build tools.

## Cloudflare builds

Cloudflare Workers Builds reads `.node-version` to select Node.js before running
install, build, and deploy commands. This matches pnpm's managed runtime in
`package.json`. Cloudflare reads the pnpm version from `packageManager`.
No dashboard `NODE_VERSION` or `PNPM_VERSION` overrides are needed.

The connected build uses `pnpm run build` and `npx wrangler deploy`. With
`.node-version`, the default `npx` deploy command uses the required Node.js version
instead of Cloudflare's default. Wrangler then reads the deployment configuration
generated by the Cloudflare Vite plugin from `wrangler.jsonc`.

Keep Worker domains, bindings, and compatibility settings in `wrangler.jsonc`.
Its runtime variables do not configure the build image's Node.js or pnpm version.

Reference: [Cloudflare build image configuration](https://developers.cloudflare.com/workers/ci-cd/builds/build-image/).
